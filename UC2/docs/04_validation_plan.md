# UC2 validation plan

Validation proceeds in gates: strict schema/config validation; ID, relationship, twin and BPMN integrity; deterministic baseline/nominal execution; passive-observation and privacy invariants; loss/overflow and dependency-failure branches; evidence/custody verification; hidden-truth separation; graph competency queries; 100-sample uncertainty analysis; interface-contract review; automated tests; and final SHA-256 manifest verification. Invalid input fails before output. Any active RF behavior or unauthorized disclosure is a release blocker.
