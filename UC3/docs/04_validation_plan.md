# UC3 validation plan

Validation order is schemas → identifiers/cross-references → configuration → graph → BPMN XML → deterministic dynamics → invariants → experiment assertions → evidence/custody → hidden-truth separation → contracts → clean installation → manifest. Invalid input must fail before output.

The validation matrix uses Complete, Partial, Missing, Not Applicable, or TBD and links evidence. Software assertions establish internal consistency only; they do not certify nuclear safety, protocol conformance, legal compliance, or pilot KPIs.
